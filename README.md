# HTTP Download Benchmark

Небольшой CLI-скрипт для замера последовательной загрузки по HTTP(S). Делает
заданное число GET-запросов, читает тело потоком и считает время, объём и скорость.
Использует только стандартную библиотеку Python и не сохраняет файл на диск.

## Что умеет

- Выполняет N запросов по одному, без параллельности.
- Читает ответ чанками по 64 КиБ, поэтому не зависит от размера файла.
- Для каждого запроса показывает статус, время, полученные байты и ошибку.
- Считает среднее время, min/max, общий объём, МБ/с и Мбит/с.
- Показывает причины ошибок в конце сводки.
- Следует редиректам и обрабатывает таймауты, не-2xx ответы и обрывы.

## Запуск

```bash
python main.py --help
```

Пример с публичным тестовым URL:

```bash
python main.py "https://speed.cloudflare.com/__down?bytes=10000000"
```

Пять запросов с таймаутом 120 секунд:

```bash
python main.py "https://speed.cloudflare.com/__down?bytes=10000000" -n 5 --timeout 120
```

Это просто демонстрационный источник данных. Подставьте URL своего файла.
На Windows вместо `python` можно использовать `py`.

### Аргументы

| Аргумент | Описание |
|---|---|
| `url` | Обязательный URL со схемой `http://` или `https://`. |
| `-n`, `--requests COUNT` | Число запросов, целое от 1. По умолчанию 10. |
| `-t`, `--timeout SECONDS` | Таймаут одного запроса в секундах. По умолчанию 30. |
| `-h`, `--help` | Справка. |

## Единицы

Объём считается в десятичных мегабайтах: `1 МБ = 1 000 000 байт`. Это не мебибайты.
Скорость в Мбит/с использует десятичные мегабиты: `1 Мбит/с = 1 000 000 бит/с`.
В одном байте 8 бит, поэтому `1 МБ/с = 8 Мбит/с`. Время выводится в миллисекундах,
среднее значение с двумя знаками после запятой.

## Расчёт скорости

Считается общий объём, делённый на общее время успешных запросов:

```text
B_total = сумма байт по успешным запросам
T_total = сумма времени успешных запросов
V_MB/s   = B_total / T_total / 1 000 000
V_Mbit/s = V_MB/s * 8
```

Это агрегированная скорость, а не среднее арифметическое скоростей отдельных
запросов. Большой запрос влияет на результат пропорционально своему объёму.

Для примера выше:

```text
B_total = 10 * 8 388 608 = 83 886 080 байт
T_total = 10.335270 с
V = 83 886 080 / 10.335270 / 1 000 000 = 8.116487 МБ/с
V = 8.116487 * 8 = 64.931892 Мбит/с
```

Среднее время запроса считается отдельно, как обычное среднее по успешным
попыткам. В него входят DNS, установка TCP/TLS-соединения, ожидание первого
байта и чтение тела.

## Ошибки

Если запрос завершился ошибкой, скрипт пишет её в строке запроса, продолжает
серию и возвращает код 1 после завершения. В статистику попадают только успешные
запросы. В конце выводится список причин с количеством повторов.

```text
Successful requests:        0 / 10 (0.0%)
Failed requests:            10

Failure reasons:
  10x  network error: [Errno 11001] getaddrinfo failed
```

| Код | Значение |
|---|---|
| 0 | Все запросы успешны. |
| 1 | Есть ошибки или ни один запрос не завершился успешно. |
| 2 | Неверные аргументы командной строки. |
| 130 | Запуск прерван с клавиатуры. |

Редиректы выполняются автоматически, до 10 переходов. В прогрессе виден финальный
статус, время редиректов входит в общее время запроса. Если сервер передал
`Content-Length`, скрипт проверяет, что тело получено полностью. Для chunked
ответов завершение проверяет `http.client`.

Если получилось `0 / N`, смотрите блок `Failure reasons`:

| Сообщение | Что проверить |
|---|---|
| `getaddrinfo failed` | Домен, DNS и доступность сети. |
| `CERTIFICATE_VERIFY_FAILED` | Корневые сертификаты, прокси, TLS. |
| `HTTP 403/404/429` | Доступ, путь к файлу, лимиты сервера. |
| `timeout` | Увеличить `--timeout`. |

## Таймаут

По умолчанию на один запрос даётся 30 секунд. Значение передаётся в `urllib` как
таймаут сокетных операций и дополнительно проверяется между чтениями чанков.
Это не жёсткий real-time дедлайн: DNS или одно блокирующее чтение могут занять
чуть больше времени. Для больших файлов и медленного канала увеличьте значение,
например до 300 секунд.

## Ограничения

- Запросы выполняются по одному, это не проверка максимальной пропускной
  способности канала.
- Каждый запрос открывает новое соединение. DNS, TCP и TLS входят в измеренное
  время. На маленьких файлах накладные расходы заметны.
- Кэш CDN может искажать результат. Первый запрос может идти на origin,
  последующие уже из кэша. Скрипт не добавляет cache-busting параметры.
- Wi-Fi, VPN, прокси, загрузка CPU и TLS-шифрование влияют на замер.
- Тело не сохраняется, поэтому проверить целостность файла после загрузки нельзя.
- Если нет `Content-Length` и сервер закрывает соединение вместо chunked, ранний
  обрыв не всегда можно отличить от нормального конца.
- Скрипт не запрашивает сжатие. Если сервер всё равно вернул `Content-Encoding`,
  считаются полученные байты без распаковки.
- `urllib` учитывает переменные окружения `HTTP_PROXY` и `HTTPS_PROXY`.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты не требуют внешних пакетов. Используется локальный HTTP-сервер и проверяются
успешный ответ, редирект, 404, chunked, таймаут, оборванный `Content-Length`,
сводка и разбор аргументов.

CI настроен в `.github/workflows/tests.yml` для Python 3.9, 3.12 и 3.14.

## Требования

- Python 3.9 или новее.
- Стандартная библиотека: `urllib`, `argparse`, `http.client`, `unittest`.
- Внешних пакетов нет, поэтому `requirements.txt` не нужен.
